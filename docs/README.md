# Public Resource Map docs

Start with the [main README](../README.md). This folder does two jobs: it is the Starlight docs site deployed at `/prm/docs/`, and it holds the files the README links to. The site build ignores this file, `getting-started.md` and `images/`.

| Path | What it covers |
|---|---|
| [getting-started.md](getting-started.md) | Full local setup: env vars, seed, sign-in, the admin, tests, building this site |
| [images/](images/shots.md) | The screenshots, GIF and diagram in the README, and how each was made |
| [src/content/docs/](src/content/docs/) | The site's own pages: [what PRM is](src/content/docs/index.mdx), [HTTP API](src/content/docs/api.mdx), [data model](src/content/docs/data.mdx), [ingestion](src/content/docs/ingestion.mdx) |
| [diagrams/](diagrams/) | archify sources for the site's two diagrams, `architecture.json` and `ingestion.json` |
| [public/diagrams/](public/diagrams/) | The compiled diagram pages, committed so the site builds on a machine without archify |
| [scripts/](scripts/) | `sync-corpus.mjs` copies `corpus/wiki/` into the site; `build-diagrams.mjs` compiles the diagrams |

The rest is the site's own configuration: `astro.config.mjs` with the sidebar and the `/prm/docs/` base path, `package.json`, `tsconfig.json`, `typedoc.json`, `src/content.config.ts`, the diagram embed in `src/components/` and the theme in `src/styles/`.

Each build regenerates three gitignored folders. `src/content/docs/wiki/` is copied from `corpus/wiki/`, `public/reference/` is TypeDoc over `shared/`, and `dist/` is the built site. Build the site with `npm run docs -w docs` from the repo root.

## On the site

Going deeper: the [project wiki](../corpus/index.md) has the decisions, the glossary, the status and the briefs that built the app.
